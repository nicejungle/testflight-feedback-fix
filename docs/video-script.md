# testflight-feedback-fix 介绍视频文案

> 时长：约 3 分钟 | 风格：技术向但通俗 | 语言：中文

---

## 开场（15秒）

做 iOS 开发的朋友们，有没有遇到过这种情况——

TestFlight 测试的时候，测试员提了一堆反馈，你一条一条看，一个一个改，改完编译、测试、打包、上传……等你发完新版，可能已经过去半天了。

今天给大家介绍一个我们公司内部开发、现在开源出来的工具，能把这整个过程**全部自动化**。

---

## 这是什么（20秒）

它叫 **testflight-feedback-fix**。

一句话总结：**TestFlight 反馈进来 → AI 自动读反馈、改代码、跑测试 → 验证通过后自动发新版到 TestFlight。**

整个过程不需要你打开电脑。你睡一觉起来，测试员昨晚提的 bug，已经修好、发版、测试员已经在用新版了。

---

## 怎么运作的（45秒）

具体流程是这样的：

**第一步**，你的 Mac Mini 每 15 分钟去 App Store Connect API 拉一次最新的 TestFlight 反馈——包括截图、崩溃日志、文字描述。

**第二步**，如果有新反馈，自动调用 Claude Code 来分析。Claude 会读你的代码库，理解反馈说的是什么问题，然后直接改代码、提交。

**第三步**，改完之后不是直接发版——它会先编译验证，然后跑相关的单元测试。如果测试不过，Claude 会看错误日志，自己修，再跑一遍。

**第四步**，全部通过后，自动推送到 release 分支，触发 Fastlane 构建上传到 TestFlight。

从反馈提交到新版本上线，大概 **10 到 15 分钟**。

---

## 成本（15秒）

这个方案最大的优势是——**零额外成本**。

- AI 用的是你 Claude Code 订阅的额度，不调 API、不额外收费
- 构建跑在你自己的 Mac 上，不用 GitHub Build 也不用 Xcode Cloud
- GitHub Actions 对 self-hosted runner 免费

你只需要一台一直开着的 Mac，就够了。

---

## Dashboard（20秒）

我们还做了一个实时监控面板，通过 Tailscale 在手机上随时能看。

能看到什么呢：
- Claude 正在改哪个文件、思考了什么
- 哪些反馈已处理、哪些待处理
- 构建是否通过、测试结果
- 每一个修复提交点开能看代码 diff

还能直接在面板上操作——忽略某条反馈、针对某条单独触发修复、停止正在跑的任务。

---

## 安全保障（15秒）

你可能会担心——AI 改代码靠谱吗？万一改出 bug 怎么办？

我们做了几层保护：
- 改完必须**编译通过**
- 改完必须**跑单元测试**，只跑受影响的测试，不是全跑
- 如果失败，AI 会看错误自己修一次
- 两次都失败就**自动回滚**，什么都不会推送

不会有坏代码上线。

---

## 谁适合用（15秒）

这个工具特别适合：
- **独立开发者**——一个人搞不过来测试反馈的时候
- **小团队**——没有专职 QA 的 2-5 人团队
- **内测阶段**——频繁迭代、快速响应测试员反馈

只要你的项目有单元测试、有 TestFlight 在跑，就能用。

---

## 怎么开始（20秒）

开源的，MIT 协议，GitHub 上搜 **testflight-feedback-fix**。

如果你用 Claude Code，一行命令就能装：

```
claude -p "Install testflight-feedback-fix into this project"
```

它会自动帮你配 workflow、配 Fastlane、配定时任务。

或者你也可以按 README 手动配，三步：装 runner、拷文件、设 secrets。
